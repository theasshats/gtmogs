Maintained-continuation release of GTMOGS for Project Commonwealth (theasshats/gtmogs, branch `pcmc/main`). LGPL-3.0-only; complete corresponding source is this repository at the release tag.

## Fixed: the Xaero's integration was never registered — markers and map buttons now exist

Root cause of "prospected in chat, nothing on the map": upstream gtmogs kept GTCEu's Xaero renderer classes but dropped the registration mixins that hand them to Xaero's mods, so the entire Xaero layer pipeline was unreachable on **every** Xaero version (bytecode-verified: no code path constructed the element renderers). The WM 1.40 `ModSettings` field deletions fixed in `1.0.6-pcmc.1` were real but latent — they could only crash once registration existed.

This release ports the three registration mixins from GTCEu's 1.21 branch (LGPL-3.0, the same lineage this mod was extracted from):

- `MapElementRenderHandlerBuilderMixin` — registers the ore-vein layer with the world map.
- `MinimapFBORendererMixin` — registers it with the minimap and over-map render handlers.
- `GuiMapMixin` — adds the layer toggle button to the fullscreen world map (position from the `compat.minimap` anchor/direction/offset options; adapted to this mod's pre-`xaero.lib` button class, which uses `CursorBox` tooltips).

Behavior notes:

- The vein layer starts **hidden**: toggle it with the new button on the fullscreen map (bottom-left by default). The toggle drives the world map, minimap, and over-map rendering together.
- Markers show **prospected** veins — right-click a vein ore to prospect, as before.
- `compat.minimap.toggle.xaerosMapIntegration: false` disables all of it, including the mixins' effects.

## Also in this release

- `GTMixinPlugin`'s mod-presence gating was inert due to a package-name typo (`quantumgarbagee`); fixed, so compat mixins only apply when their mod is actually loaded.
- Compile-time Xaero dependencies moved from 1.39-era CurseForge pins to Xaero's official maven (`chocolateminecraft.com/maven`) at WM **1.40.16** / MM **25.3.13** — the pair this release is verified against (and two fewer cursemaven dependencies).
- Ships a static `assets/gtmogs/lang/en_us.json` with the user-facing command and button strings: upstream's datagen output never made it into any released jar, so these rendered as raw translation keys. Drop this file if datagen packaging is ever fixed.

## Verification

- Member-level reference check against the newest Xaero builds: clean (release-workflow gate).
- Mixin injection targets are invisible to the member-level check, so they were verified separately: the targeted methods (`MapElementRenderHandler$Builder.build`, `MinimapFBORenderer.loadFrameBuffer`, `GuiMap.init`) and shadowed members were checked for presence and bytecode drift across WM 1.40.11 (GTCEu's working baseline) / 1.40.16 (pack) / 1.41.0 (newest) and MM 25.3.10 / 25.3.13 / 26.1.0.
- **Needs the in-game check** (this is the fix for the map symptom): with WM 1.40.16 + MM 25.3.13, prospect a vein, open the fullscreen map, toggle the new ore-vein button — markers should appear on both the fullscreen map and the minimap.
