Maintained-continuation release of GTMOGS for Project Commonwealth (theasshats/gtmogs, branch `pcmc/main`). LGPL-3.0-only; complete corresponding source is this repository at the release tag.

## New: surface-biome sampling for vein eligibility (config-gated)

Two new options under `worldgen.oreVeins`:

- **`sampleSurfaceBiome`** (default **false** — vanilla GTMOGS behavior): when enabled, the vein lottery decides a grid cell's eligible veins from the biome sampled at a fixed high y instead of the vein center's y=0. Stock behavior samples the 3D noise biome at y 0–3, so cave-biome pockets there (dripstone, lush caves, deep dark) veto — or, for cave-tagged veins, capture — the cell regardless of where the vein body actually generates. With this on, the ore under a mountain is the mountain's ore.
- **`surfaceBiomeSampleY`** (default **200**): the fixed sample height. Cave biomes are placed by depth below the *local* surface, so a sample height that sits inside tall terrain still reads as caves — with tall worldgen like Terralith, y=100 is inside many mountains, which is why the default is 200 and the height is tunable without a rebuild. Very high values can instead catch floating sky biomes (e.g. Terralith skylands) where those generate.

The implementation samples the noise biome source at a fixed y rather than using heightmaps: neighbor-chunk heightmaps are unavailable or unstable during worldgen, while the noise biome source is deterministic at any height.

## Stated design interaction

While `sampleSurfaceBiome` is enabled, **cave-biome entries in vein biome tags no longer match anything** — a cell's biome is always a surface (or sky) biome. For Project Commonwealth that means palladium's `dripstone_caves`/`deep_dark` homes stop producing anchors and palladium needs a pack-side re-home (theasshats/project-commonwealth#318, E3.3). This is expected, not a bug.

## Scope and migration

- Affects newly generated chunks only; veins already recorded in existing chunks are untouched.
- The flag changes vein *selection* for not-yet-generated grid cells: the same seed with different settings picks different veins. Per-cell determinism for a fixed config is unchanged.
