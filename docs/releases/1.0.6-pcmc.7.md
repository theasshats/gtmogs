Maintained-continuation release of GTMOGS for Project Commonwealth (theasshats/gtmogs, branch `pcmc/main`). LGPL-3.0-only; complete corresponding source is this repository at the release tag.

Fixes a crash when the Xaero map renders an ore-vein marker.

## Fixed

- **Opening the world map (or showing the minimap) with the ore-vein layer on could crash** (`NoSuchElementException` in `MapIntegrationUtils.getFirstBlockFace`). The marker icon was built from `getQuads(state, Direction.NORTH, ...).getFirst()`, but a block model's quads only live under a specific cull face for standard full-cube models; cross models, ores with custom parents, and non-solid render types put their quads under the general (`null`) direction, leaving the north-face list empty so `getFirst()` threw and took down the render. The lookup now checks the general quads first, then every face, and falls back to the model's particle sprite (always present), so it returns a sprite for any block model. Both the world-map and minimap marker renderers route through this method.

This only became reachable in `1.0.6-pcmc.4`, which registered the Xaero map layers for the first time — the render path had never run before.

## Verification

- Member-level reference check against the newest Xaero builds: clean (release-workflow gate). No Xaero-facing or worldgen code changed.
- In-game check: with veins prospected and the ore-vein layer toggled on, open the fullscreen world map and confirm the minimap renders — markers should draw with an ore-face icon and no crash.
