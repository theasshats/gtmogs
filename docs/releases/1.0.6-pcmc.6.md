Maintained-continuation release of GTMOGS for Project Commonwealth (theasshats/gtmogs, branch `pcmc/main`). LGPL-3.0-only; complete corresponding source is this repository at the release tag.

Fixes from the prospect investigation's log analysis.

## Fixed

- **The gtmogs JEI plugin crashed on world join with JEI 19.27+, taking the Ore Vein Diagram with it.** Upstream built the category icon from `BuiltInRegistries.BLOCK.get("minecraft:raw_iron")` — `raw_iron` is an item id, not a block id, so the lookup returned air, and newer JEI rejects empty drawable stacks (`Ingredient is invalid and cannot be used as a drawable ingredient`). Older JEI tolerated the empty icon, which is why the diagrams used to show. The icon now uses the item registry.
- **Prospecting an ore with no vein record now says so** (actionbar: "No vein records within N blocks of this ore"). The dominant confusion case: scattered small-ore blobs use the same ore blocks as veins but have no vein record, so right-clicking them silently did nothing — indistinguishable from prospecting being broken. Real vein ores still prospect as before.
- **Prospecting now also fires when another mod cancels the right-click** (`receiveCanceled = true`): prospecting is read-only, so claim/protection mods canceling block interactions should not suppress it.

## Verification

- Member-level reference check against the newest Xaero builds: clean (release-workflow gate). No Xaero-facing or worldgen code changed.
- In-game checks: JEI shows the Ore Vein Diagram category again (icon: raw iron); right-clicking a small-ore blob shows the actionbar notice; right-clicking ore inside a recorded vein prospects and drops markers on the map.
