Maintained-continuation release of GTMOGS for Project Commonwealth (theasshats/gtmogs, branch `pcmc/main`). LGPL-3.0-only; complete corresponding source is this repository at the release tag.

Diagnostic build for the "right-click no longer prospects" report: every failure mode in the prospect chain is silent upstream, so this release makes each stage observable, plus small fixes the investigation surfaced.

## New

- **`/gtmogs prospect [radius]`** (permission level 2): bypasses the right-click path entirely — looks up the recorded veins around the player, force-sends them to the player's map, and reports each stage's numbers: how many vein-ore blocks are registered, how many recorded veins are within range, how many were sent, and how many the packet's above-surface filter would drop. One command output localizes a silent failure:
  - `0 vein-ore blocks registered` — vein definitions did not construct (datapack side).
  - `0 recorded veins within range` while the census shows veins — cache lookup (grid keying) is broken.
  - veins sent but no markers appear — packet/client/render side.
  - command works end-to-end but ore right-click still does nothing — the failure is in the right-click layers (event delivery, vein-ore set membership, or exact block-state match).
- Prospect-path debug logging, gated on `dev.debug`: each ore right-click logs recorded/matched counts, and the prospect packet logs how many veins its above-surface filter dropped.

## Fixed

- `/gtmogs place_vein` now records the placed vein in the server cache, so placed veins prospect, render on maps, and appear in the census (previously they only placed blocks).
- The prospect chat notification key (`message.gtmogs.new_veins.name`) now has a translation: "Prospected new vein: %s". It has rendered as a raw key since upstream 1.0.6.

## Verification

- Member-level reference check against the newest Xaero builds: clean (release-workflow gate). No Xaero-facing code changed in this release.
- Diagnostic recipe: update, then (1) right-click a vein ore and check `debug.log` for the `Prospect by ore at ...` line; (2) run `/gtmogs prospect`; report both outputs.
