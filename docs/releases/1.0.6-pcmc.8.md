Maintained-continuation release of GTMOGS for Project Commonwealth (theasshats/gtmogs, branch `pcmc/main`). LGPL-3.0-only; complete corresponding source is this repository at the release tag.

Cleans up how ore-vein markers are drawn on the Xaero maps.

## Changed

- **Vein markers now render the ore's actual item icon** instead of a hand-rolled block-face texture multiplied by the block's map color. The old path produced muddy, hard-to-read markers (the map-color tint shifted every ore's hue) and, for ores whose block models don't expose a simple cull-face quad, sampled the block atlas wrong so a marker looked like a small grid of unrelated textures. Rendering the item sidesteps both: true colors, a recognizable inventory-style icon, and no manual atlas-UV handling. The colored frame around each marker (the ore's map color) is kept, so markers stay colour-coded by ore. A block with no item form falls back to its flat particle sprite.

`compat.minimap.oreIconSize` (default 32) still controls marker size; lower it if markers feel large where veins are dense.

This render path has only existed since `1.0.6-pcmc.4` (which first registered the Xaero layers) and was first seen in `pcmc.7` once markers stopped crashing.

## Verification

- Member-level + mixin-target checks against the newest Xaero builds: clean (release-workflow gate). No Xaero-facing API surface changed.
- In-game check (this is a visual change): prospect veins, open the world map and minimap with the ore-vein layer on — markers should read as recognizable ore icons in true colors with a colored frame, not tinted squares or texture-grid smears. Watch that the item icon renders in front of the map (item rendering uses depth); if a marker hides behind map tiles, say so.
